## 项目是什么

这是一个 **DSH（DeepSeek Harness）插件**，把一个**真人微信小号**变成你的"秘书"：你在微信里给它发文字、文件，它就替你在电脑上干活（查资料、改文件、跑命令、整理东西……），再把结果发回微信。

它**不是**聊天机器人，也不是自动客服：没有群聊自动接话、没有营销话术、不做支付/转账。它只服务白名单里的主人（默认只有你自己），目标是"少打扰人、多把事办完"。

**重要：本仓库不包含"桥"（微信客户端操作层）。** 桥负责登录微信、收发消息、下载附件（涉及 UI 自动化，易被平台针对），由使用者自备。本项目只提供**接口约定**与 Host 侧的编排逻辑（DSH 插件 + 秘书模式 preset）。

**English**: This is a DSH (DeepSeek Harness) plugin that turns a real WeChat alt account into a "secretary": you send it text/files on WeChat, it does work on your computer (research, edits, commands, cleanup) and replies on WeChat. It is not a chatbot, not a customer-service bot: no group auto-replies, no payments. It serves only the whitelisted owner. **This repo does NOT include the bridge** (the WeChat client automation layer). You provide your own bridge; this project only defines the HTTP contract and the host-side orchestration.

## 能力清单

- **会话队列**：每个微信 chat 一条串行队列；游标只在处理成功后提交，失败按次数重试，超限才跳过并记日志，不会重复投递。
- **积压合并**：宿主离线/桥掉线时攒下的消息，按同一 chat 跨轮累计；超过阈值（默认 10 分钟且 ≥3 条）合并成一条摘要交给会话，附件按原顺序编号挂在行内；不足阈值逐条处理并标注"这条是 N 分钟前的"。
- **回执回流（两档）**：默认不回"收到，正在办"；任务超过 `slowNoticeSec`（默认 180 秒）才补一句进度说明，之后每 `progressEverySec` 再报一次"已跑 N 分钟"。回答可按 `reflowMode` 选择 `raw`（原样）或 `summary`（压缩成几句）。
- **跨会话派活**：`wechat_secretary_sessions` 列出同工作区的 DSH 会话；`wechat_secretary_dispatch` 支持 `queue`（派活，会话忙则排队）与 `steer`（插话，默认关闭）；派活前会检测目标会话是否卡死（`turn/end blocked`），卡死直接拒绝并建议换会话。
- **记忆与情绪**：`plugin/memory.js` 纯文件、零依赖——主人画像、事实（带有效区间，可回答"你上次说的是什么"）、任务台账、每日摘要；按"关键词命中 × 时间衰减 × 重要度"检索，注入有预算上限。情绪是对回答末尾隐藏标记的解析，回微信前剥掉，只用于口吻，不改变事实。
- **审批与叫停**：秘书会话的审批策略设为 `never`（手机上看不到电脑端弹窗），高危动作由 `tools.guard` 硬拦截（删文件/装插件/改系统/工作区外写/外网写），必须先在微信里经 `wechat_secretary_approve` 批准，10 分钟内一次性放行。微信里发「停 / 停止 / 取消 / 别做了」可取消正在跑的单。
- **自愈**：DSH 重启后插件会探活并尝试拉起本地桥（`autoStartSidecar`，默认关闭，需配置路径）；桥的看护脚本失败 5 次会停手并打明显日志。
- **台账与可观测**：`workitems.jsonl` 记录每单的 received/working/waiting_human/done/dropped/failed；`GET /wechat-secretary/workitems` 提供只读汇总（需 DSH Host 侧）。

```
                               ▼

```

## 安装与配置

### 0. 前置

- Windows + 已登录小号的微信 PC 客户端（建议专机/虚拟机，只登小号）；
- 一个**自备的桥**：至少实现下面四个接口，并能稳定收发文字与文件；
- DSH（DeepSeek Harness）桌面版，能安装本地插件 bundle。

### 1. 安装两个 bundle

- `plugin/`：渠道插件（Host 半边，常驻，负责轮询/派活/回发/台账/记忆）。
- `preset/`：秘书模式（persona + 工具面 + 红线），提供 `secretary` 模式。

把这两个目录分别作为 bundle 安装（或在 profile 的 `cordis.patch.yml` 里按 `insert` 行引入），然后启用。安装后新建会话选择 **Secretary** 模式即可。

### 2. 桥的接口约定（本仓库只约定，不实现）

```
GET  /inbox?since=<seq>&limit=<n>
  → { "entries": [ {
        "seq": 1, "chat": "wxid_xxx", "sender": "wxid_xxx",
        "type": "text", "content": "…",

        "latency_s": 37.2,
```

桥要把"主人发给小号的消息"和"小号发给主人的消息"区分开（后者不要回环投递），并自己做去重（同一 local_id 只投一次）。

### 4. 安全建议

- 只登小号；小号只加主人；白名单只填主人；不要用大号跑自动化。
- 不要把桥、微信数据目录、状态文件提交到公开仓库（本仓库的 `.gitignore` 已忽略 `data/`、`*.log`）。
- 平台条款与风控由使用者自行承担；本项目不含任何绕过平台限制的实现。

## 已知限制

- **不含桥**：没有桥就没有收发；接口虽简单，但微信客户端操作本身容易受版本更新影响，需自行维护。
- **延迟**：消息经桥轮询发现，常见 30~40 秒才进队列；对实时对话不友好，适合"派活—回结果"。
- **群聊/支付**：不做群聊监听与自动接话，不碰支付、转账、红包、账号设置。
- **审批**：手机端无法点 DSH 原生审批，因此采用"策略 never + 硬拦截 + 微信远程审批"；`steer`（插话）默认关闭。
- **单机单小号**：同一微信账号同一时刻只能在一台电脑上登（微信自身规则）；多机部署需自行解决切换。
- **文本发送**依赖桥的回读校验；桥若不支持回读，只能以桥的返回为准。
